# Подключение Telegram-бота к audiodoc

Это руководство связывает `bot-obormot` и `audiodoc`. Бот отправляет аудио и документы в audiodoc по HTTP; текстовый чат идёт напрямую от бота к LLM-серверу с OpenAI-совместимым API. Изображения, GIF, стикеры и видео бот обрабатывает самостоятельно.

Связанная документация: [HTTP API audiodoc](api.md), [примеры развёртывания](../deploy/README.md), [репозиторий бота](https://github.com/WhlteAdmln/bot-obormot) и [настройка бота](https://github.com/WhlteAdmln/bot-obormot#подключение-audiodoc).

## 1. Компоненты и поток запросов

```text
Telegram
   |
   v
bot-obormot (машина A)
   |-- текст -----------------------> LLM-сервер: POST /v1/chat/completions
   |-- голос/аудио, multipart file -> audiodoc: POST /transcribe
   |-- документ, multipart file ----> audiodoc: POST /process-document
   |
   +-- история диалога ------------> локальная SQLite

Обычно машина B размещает одновременно audiodoc и LLM-сервер.
```

Бот формирует пути эндпоинтов на основе `AUDIODOC_URL`. Укажите только базовый URL (например, `http://10.8.0.1:8000`), без `/transcribe` и `/process-document`.

## 2. Соответствие настроек

| Назначение | `bot-obormot` | `audiodoc` | Примечание |
| --- | --- | --- | --- |
| Базовый URL | `AUDIODOC_URL` | host/port Uvicorn | Только базовый URL; бот добавляет пути эндпоинтов |
| Ключ распознавания | `AUDIODOC_AUDIO_KEY` | `AUDIODOC_AUDIO_KEY` | Значения должны совпадать |
| Ключ документов | `AUDIODOC_DOCUMENT_KEY` | `AUDIODOC_DOCUMENT_KEY` | Значения должны совпадать и отличаться от ключа аудио |
| Тайм-ауты запросов | `AUDIODOC_AUDIO_TIMEOUT`, `AUDIODOC_DOCUMENT_TIMEOUT` | — | В секундах; настройки только для бота |
| Ротация ключей | Один активный ключ | Несколько ключей через запятую | Позволяет выполнить переключение без окна отказа |
| Поле загрузки | `file` | `file` | `multipart/form-data` |
| Ответ распознавания | Бот читает `text` | `{text, language, duration}` | Все три поля входят в контракт ответа |
| Ответ документа | Бот проверяет `format`, `text`, `characters` и обрабатывает `truncated` | `{format, text, characters, truncated}` | При `truncated=true` бот сообщает, что документ слишком большой |

`GET /health` не требует ключа. Для `GET /ready` и `POST /process-document` нужен `AUDIODOC_DOCUMENT_KEY`; для `POST /transcribe` — `AUDIODOC_AUDIO_KEY`. Используйте разные ключи. В production оставляйте `ALLOW_UNAUTHENTICATED=false`.

Для миграции audiodoc читает `WHISPER_API_KEY` и `DOCUMENT_API_KEY` как запасные значения, если соответствующий новый ключ пуст. Бот сохраняет совместимость с `WHISPER_API_URL`, `DOCUMENT_API_URL`, `WHISPER_API_KEY`, `DOCUMENT_API_KEY`, `WHISPER_TIMEOUT` и `DOCUMENT_TIMEOUT` в течение двух минорных релизов. Новая настройка имеет приоритет над старой. При использовании старого имени при запуске выводится предупреждение об устаревании.

## 3. Действующие лимиты

| Лимит | Бот | audiodoc | Фактическое поведение |
| --- | ---: | ---: | --- |
| Размер загружаемого файла | 20 МиБ | Аудио 25 МиБ; документ 50 МиБ | Для обоих типов файлов строже ограничение бота — 20 МиБ |
| Длительность аудио | 300 с | 600 с | Бот отклоняет аудио длиннее 5 минут ещё до отправки |
| Текст для LLM | 12 288 символов | До 2 000 000 символов по умолчанию | Бот просит audiodoc вернуть не более 11 264 символов, оставляя 1 024 символа для метки, имени файла и подписи |
| Тайм-аут запроса | Аудио 180 с; документ 300 с | Обработка документа — 180 с | Ожидание в очереди также входит в тайм-аут запроса бота; настройте его под свою нагрузку |
| Очередь ожидания | — | 4 ожидающих задачи распознавания; 4 задачи документов | При заполнении очереди возвращается `503` с `Retry-After: 30` |
| Активная обработка документов | — | 2 worker-процесса | Пропускная способность зависит от CPU, RAM, диска и стоимости OCR |
| Активное распознавание | — | По умолчанию 1 worker | Whisper может конкурировать с LLM за CPU/GPU ресурсы |

Бот отправляет multipart-поле `max_characters=11264`. Это уменьшает объём извлечения на audiodoc и оставляет место под подпись документа, имя файла и необязательную подпись Telegram. Не увеличивайте значение выше лимита входного текста бота без изменения и тестирования его собственной валидации.

## 4. Выберите сетевую схему

### Сценарий 1 — оба сервиса на одной машине

Самый простой вариант для локальной проверки. Запустите audiodoc, LLM-сервер и бота на одном хосте.

`audiodoc/.env`:

```ini
AUDIODOC_AUDIO_KEY=REPLACE_WITH_RANDOM_KEY_1
AUDIODOC_DOCUMENT_KEY=REPLACE_WITH_RANDOM_KEY_2
ALLOW_UNAUTHENTICATED=false
```

Запустите audiodoc из корня проекта:

```bash
uvicorn app:app --host 127.0.0.1 --port 8000
```

`bot-obormot/.env`:

```ini
LLM_BASE_URL=http://127.0.0.1:8080/v1
AUDIODOC_URL=http://127.0.0.1:8000
AUDIODOC_AUDIO_KEY=REPLACE_WITH_RANDOM_KEY_1
AUDIODOC_DOCUMENT_KEY=REPLACE_WITH_RANDOM_KEY_2
```

Замените оба заполнителя разными случайными значениями. Соответствующие значения в конфигурациях бота и audiodoc должны совпадать.

### Сценарий 2 — две машины через WireGuard (рекомендуемая схема)

В примерах развёртывания используются адреса: машина A (бот) — `10.8.0.2`, машина B (audiodoc и LLM) — `10.8.0.1`. Это примеры; замените их, если в вашей WireGuard-сети другие адреса.

На машине B привяжите audiodoc к приватному VPN-адресу:

```bash
uvicorn app:app --host 10.8.0.1 --port 8000
```

Разрешите входящие TCP-порты `8000` (audiodoc) и `8080` (LLM) только от VPN-адреса бота `10.8.0.2`. Перед применением правил файрвола изучите [`deploy/README.md`](../deploy/README.md) и `deploy/ufw-rules.sh.example`. Не открывайте оба сервиса в публичный интернет.

`bot-obormot/.env` на машине A:

```ini
LLM_BASE_URL=http://10.8.0.1:8080/v1
AUDIODOC_URL=http://10.8.0.1:8000
AUDIODOC_AUDIO_KEY=REPLACE_WITH_RANDOM_KEY_1
AUDIODOC_DOCUMENT_KEY=REPLACE_WITH_RANDOM_KEY_2
```

Используйте те же два ключа в `audiodoc/.env` на машине B. Обычный HTTP внутри WireGuard допустим: VPN-туннель шифрует трафик между узлами.

### Сценарий 3 — HTTPS через nginx вместо WireGuard

Оставьте Uvicorn привязанным к loopback на машине B, а TLS завершайте на nginx. Настройте allow-list IP-адреса бота и используйте сертификат, которому доверяет системное/Python-окружение бота.

```ini
AUDIODOC_URL=https://backend.example.internal
```

Оставьте те же совпадающие Bearer-ключи, что заданы в audiodoc. Не отключайте проверку сертификата в боте. LLM-сервер также должен использовать защищённый канал или приватную сеть; не открывайте его напрямую в интернет.

### Ресурсы

LLM и Whisper на общей машине B могут конкурировать за CPU, RAM и видеопамять. По умолчанию audiodoc использует CPU (`WHISPER_DEVICE=cpu`). При переносе Whisper на GPU учитывайте потребности LLM в VRAM и настройте ограничения ресурсов в примере systemd.

## 5. Проверка соединения

Выполняйте команды с машины A (где работает бот), а не только с машины B. Так проверяются и сервисы, и маршрутизация с правилами файрвола. Примеры ниже рассчитаны на WireGuard; для другой схемы замените адрес хоста.

Задайте ключи в текущем shell для тестового сеанса. Не вставляйте настоящие ключи в задачи, логи или общие записи терминала:

```bash
export AUDIODOC_DOCUMENT_KEY='your-document-key'
export AUDIODOC_AUDIO_KEY='your-audio-key'
```

1. Liveness, ключ не нужен. После загрузки модели ожидается `loaded: true`:

```bash
curl -fsS http://10.8.0.1:8000/health
```

1. Диагностика зависимостей документов, нужен ключ документов. Ожидаются булевы значения и список языков:

```bash
curl -fsS http://10.8.0.1:8000/ready \
  -H "Authorization: Bearer ${AUDIODOC_DOCUMENT_KEY}"
```

1. Извлечение документа. Ожидаются поля `format`, `text`, `characters` и `truncated`:

```bash
echo 'Example document text.' > /tmp/audiodoc-sample.txt
curl -fsS \
  -H "Authorization: Bearer ${AUDIODOC_DOCUMENT_KEY}" \
  -F "file=@/tmp/audiodoc-sample.txt" \
  -F "max_characters=11264" \
  http://10.8.0.1:8000/process-document
```

1. Распознавание. Используйте короткий корректный файл `.ogg`; ожидаются `text`, `language` и `duration`:

```bash
curl -fsS \
  -H "Authorization: Bearer ${AUDIODOC_AUDIO_KEY}" \
  -F "file=@voice.ogg" \
  http://10.8.0.1:8000/transcribe
```

В завершение отправьте боту в Telegram короткое голосовое сообщение и небольшой документ `.txt`. Успешные прямые запросы `curl` не заменяют эту сквозную проверку.

## 6. Ротация ключей без перерыва авторизации

API audiodoc принимает несколько действующих ключей через запятую. Для каждого ключа выполните процедуру отдельно:

1. В `audiodoc/.env` задайте ключ эндпоинта как `OLD_KEY,NEW_KEY` и перезапустите audiodoc. Во время переключения будут приниматься оба значения.
2. Замените соответствующий ключ в `.env` бота и перезапустите бота.
3. После проверки запросов удалите `OLD_KEY` из `.env` audiodoc и снова перезапустите audiodoc.

Не объединяйте ключи Whisper и документов: они защищают разные эндпоинты.

## 7. Диагностика

| Симптом | Вероятная причина | Что проверить |
| --- | --- | --- |
| Бот не может связаться с сервисом | Неверный host/port, сервис остановлен, файрвол блокирует трафик или Uvicorn слушает только loopback | Вызовите `/health` с машины A; проверьте `ss -tlnp` и правила UFW на B |
| HTTP `404` | В URL отсутствует путь эндпоинта | Добавьте `/transcribe` или `/process-document` в URL бота |
| HTTP `401` | Ключи не совпадают или перепутана группа ключей | Сверьте ключ аудио бота с `AUDIODOC_AUDIO_KEY`, а ключ документов — с `AUDIODOC_DOCUMENT_KEY`, не раскрывая их значения |
| HTTP `503` | Whisper ещё не загружен или заполнена ограниченная очередь | Проверьте `/health`, логи сервиса и `Retry-After`; снизьте нагрузку или осторожно настройте лимиты очереди |
| HTTP `413` | Файл превышает лимит бота или сервера | Проверьте лимит бота 20 МиБ и лимиты audiodoc 25/50 МиБ |
| HTTP `400` для аудио | Аудио некорректно или длиннее серверного лимита | Сейчас бот отклоняет аудио длиннее 300 секунд; по умолчанию audiodoc допускает до 600 секунд |
| HTTP `504` или тайм-аут бота | Истёк дедлайн документа или тайм-аут клиента; время очереди также учитывается | Проверьте нагрузку и логи бэкенда перед увеличением тайм-аутов |
| Первый запуск кажется медленным | Скачивается или загружается модель Whisper | Заранее подготовьте модель, задайте `WHISPER_MODEL_PATH` и включите `WHISPER_OFFLINE=true` |

Подробности эндпоинтов и кодов состояния приведены в [описании API](api.md). Настройка сети и защита хоста описаны в [примерах развёртывания](../deploy/README.md).
